# 題材企画: `Collectors.toMap`が重複SKUで失敗し、価格スナップショットを公開できない

## 対象

| 項目 | 内容 |
| --- | --- |
| 対象言語 | Java 21 |
| 対象読者 | Stream APIでリストをMapへ集約し、同一キーの更新データを扱う中級者 |
| 難易度プロファイル | 実践・上級 |
| 選定理由 | 集約対象の更新リストに同じSKUが複数回現れることは実務で自然だが、二引数版の`Collectors.toMap`は重複キーの解決規則を持たない。公開結果、スナップショットの最終状態、標準ライブラリの例外を分けて観測し、入力順・状態更新・重複キーの三つの仮説を比較できる。 |
| 実行基盤 | Maven、Java 21、JUnit Jupiter 5.11.4 |
| フレームワーク非依存性 | 原因は`java.util.stream.Collectors.toMap`の重複キー契約である。HTTP、DI、DB、ORM、外部APIには依存せず、固定のインメモリ更新リストだけで再現する。 |

## 学習する契約

> 既存スナップショット`SKU-01=80`に対し、入力順で`SKU-01=100`、`SKU-02=200`、`SKU-01=120`をリフレッシュした場合、後着更新を採用して`SKU-01=120`、`SKU-02=200`を公開し、公開バージョンを一つ増やすべきだが、バグ状態では`REJECTED_DUPLICATE_SKU`となり、旧スナップショットが残る。

### 対象の直接原因

マージ関数なしの`Collectors.toMap(keyMapper, valueMapper)`を使うと、同じSKUから二つのMapエントリを作れない。重複キーがあり得る入力に対する「後着更新を採用する」という業務規則を、Collectorへ渡していない。

### 対象外

このラボは並列Streamの順序、複数スレッドからの同時リフレッシュ、永続化、外部価格フィードの時刻比較、金額の`BigDecimal`表現、重複データの監査・警告を扱わない。入力が出現順で確定しており、後着値を採用するという狭い規則だけを扱う。

## 再現設計

| 要素 | 決定 |
| --- | --- |
| 公開境界 | `PriceSnapshotService#refresh(List<PriceUpdate>)`、`currentPrices()`、`publishedVersion()`。 |
| 入力・初期状態 | 旧状態`SKU-01=80`を一度公開後、`SKU-01=100`、`SKU-02=200`、`SKU-01=120`の固定順リストを与える。 |
| Redの観測 | `RefreshOutcome.PUBLISHED`を期待するが、バグ状態では`RefreshOutcome.REJECTED_DUPLICATE_SKU`となる。 |
| 最終観測 | `currentPrices()`が`SKU-01=120`と`SKU-02=200`を持ち、`publishedVersion()`が`2`であることを別々に検証する。 |
| 決定性 | 時刻、乱数、並行実行、`sleep`、外部I/Oを使わず、固定リストとインメモリ状態だけを使う。 |
| 固定状態の検証コマンド | `mvn --batch-mode clean test` |
| バグ状態の確認コマンド | `git checkout 05c5fde`後に`mvn --batch-mode test -Dtest=PriceSnapshotServiceTest` |

## 仮説

| 仮説 | どう検証または除外するか |
| --- | --- |
| A: 二度目のSKUは業務ルール上、拒否すべきである | 空の初期状態で重複なし更新が公開されることと、題材契約が後着値の採用を明示することを比較する。 |
| B: 旧スナップショットのコピーや公開順序が誤っている | 新SKUだけの更新ではMapとバージョンが更新されることを対照テストで確認する。 |
| C: マージ関数なしの`Collectors.toMap`が重複キーを拒否する | 同じ更新リストを直接`toMap`へ渡したときの例外と、マージ関数を与えたときの集約結果を観測する。 |

## 予定する履歴

| 順序 | コミットの目的 | 期待する状態 |
| --- | --- | --- |
| 1 | 重複SKUの価格スナップショット公開失敗を再現する | 対象テストが`PUBLISHED`期待・`REJECTED_DUPLICATE_SKU`実際のアサーション差分で失敗する。 |
| 2 | 後着SKU更新をマージして価格スナップショットを公開する | 同じ検証が成功し、全体も成功する。 |
